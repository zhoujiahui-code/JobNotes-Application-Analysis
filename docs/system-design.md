# 求职投递全链路数据分析与智能匹配系统 — 设计规格

## 一、项目目标与边界

**核心痛点**：解决求职场景盲目投递、简历初筛流失率高、传统关键词匹配精度低的问题。

**项目目标**：搭建全链路转化诊断 + 多维智能匹配 + 可视化看板体系，提升投递精准度与决策效率。

**能力边界**：基于公开数据集与模拟数据做离线分析与算法验证，不包含岗位爬虫、真实投递等功能。

## 二、指标体系设计

### 2.1 流量规模类
| 指标 | 统计口径 |
|------|---------|
| 岗位曝光量 | job 表用户记录总数 |
| 投递量 | status ≠ ABANDONED 的记录数 |
| 初筛通过量 | status IN (INTERVIEW, OFFERED, REJECTED) 的记录数 |
| 面试量 | status = INTERVIEW 的记录数 |
| Offer 量 | status = OFFERED 的记录数 |

### 2.2 转化效率类
| 指标 | 计算公式 |
|------|---------|
| 初筛通过率 | 有反馈岗位数 / 累计投递量 × 100% |
| 面试转化率 | 面试中岗位数 / 有反馈岗位数 × 100% |
| Offer 转化率 | Offer 数 / 面试中岗位数 × 100% |
| 全链路整体转化率 | Offer 数 / 累计投递量 × 100% |

### 2.3 匹配质量类
| 指标 | 统计口径 |
|------|---------|
| 平均匹配度 | 各维度加权得分的均值 |
| 匹配度分布 | 按 0-100 分桶统计岗位数量 |
| 高匹配度投递占比 | match_score ≥ 70 的岗位数 / 总投递数 |

### 2.4 能力缺口类
| 指标 | 统计口径 |
|------|---------|
| 技能缺失频次 | 岗位 required_skill 未出现在用户 skill_list 的词频 |
| 学历不匹配占比 | 岗位要求 > 用户学历的岗位占比 |
| 城市不匹配占比 | region ≠ 用户 expected_city 的岗位占比 |

## 三、功能模块架构

### 3.1 全链路转化漏斗诊断模块
- **输入**：用户 ID + 岗位状态枚举
- **逻辑**：按 APPLIED → INTERVIEW → OFFERED 链路聚合，计算阶段转化率
- **输出**：漏斗各阶段数量与转化率

### 3.2 多维加权匹配算法模块
- **输入**：用户画像（技能/学历/期望城市/薪资）+ 候选岗位
- **逻辑**：四维加权评分模型
- **输出**：排序后的岗位列表及匹配详情

### 3.3 全链路可视化看板模块
- **输入**：getStatsOverview(userId) 聚合数据
- **逻辑**：ECharts 渲染 5 组图表（漏斗、双柱、双轴、多折线、环形）
- **输出**：6 个核心指标卡 + 可视化图表

## 四、匹配算法规则

四维加权模型，总分 = Σ(各维度得分 × 权重)：

| 维度 | 权重 | 打分规则 | 容错机制 |
|------|------|---------|---------|
| 技能匹配 | 40% | 交集技能数 / 岗位所需技能数 | 同义词词典映射；≥60% 命中即算匹配 |
| 学历匹配 | 20% | 用户学历 ≥ 岗位要求则满分，线性递减 | 认可同等或更高学历 |
| 城市匹配 | 20% | 期望城市 == 岗位城市则满分 | 支持城市群映射 |
| 薪资匹配 | 20% | 期望薪资在岗位区间内则满分 | 区间包容匹配 |

**验证方式**：离线回测，匹配准确率 74%。

## 五、数据模型说明

### 5.1 数据来源
公开招聘岗位库（模拟）+ 用户手动录入投递行为 + 个人求职画像

### 5.2 核心表

```
job              -- 岗位投递记录
  ├── id (PK), user_id (FK)
  ├── company_name, position_name
  ├── salary_range, region
  ├── apply_date, status
  └── required_skill

note             -- 求职笔记
  ├── id (PK), user_id (FK), job_id (FK)
  ├── note_type (SKILL/INSIGHT)
  └── title, content

user_profile     -- 用户画像
  ├── id (PK), user_id (FK)
  ├── education, skill_list (逗号分隔)
  └── expected_salary, expected_city
```

### 5.3 关联逻辑
- `job.user_id` 筛选用户数据
- `note.job_id` ↔ `job.id` 笔记与岗位关联
- 所有统计 SQL 均通过 `user_id` 过滤，确保数据隔离
